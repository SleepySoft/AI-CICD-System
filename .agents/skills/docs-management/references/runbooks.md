# Runbook 规范（docs/runbooks/）

在 `docs/runbooks/` 下新建或修改操作手册前必读本文件。模板见 `../assets/templates/runbook.md`。

## 何时写 runbook

满足任一条件即写：

1. 重复性操作：部署、初始化、备份恢复、密钥轮换、扩容；
2. 易错操作：步骤有顺序依赖、有不可逆环节、有已知环境坑；
3. 排障手册：有明确"现象 → 原因 → 处置"对应关系的问题。

一次性的探索操作不写；需求/规格/原理类内容分别属于 requirements/、what/、how/，不混入 runbook。

## 硬性要求

1. **每个步骤可执行**：命令完整可粘贴运行，注明执行环境（WSL / PowerShell / 容器内）。
2. **验证步骤必备**：给出验证命令与预期输出标志；优先引用 `scripts/verify*.sh`，不复制脚本内容。
3. **能脚本化的优先脚本**：超过约 5 步的固定流程应落成 `scripts/*.sh`，runbook 只写"何时跑这个脚本 + 失败怎么办"，不复制命令序列。
4. **回滚章节**：有副作用的操作必须写回滚步骤；无回滚可能的（如数据删除）在目的段显式警告。
5. **环境坑登记**：操作涉及已知坑（如 WSL 中 curl 需 `--noproxy '*'`、Keycloak 健康端点在 9000）时在步骤行内注明，并与 `AGENTS.md` 已知环境坑一节保持一致。

## 写作风格

- 面向"急于完成任务的操作者"：先步骤后解释，原理性说明压缩成一行链接到 how/ 对应文件。
- 命令块标注 shell 类型（bash / powershell）；路径用项目相对路径。
- 常见问题表只收录**实际遇到过**的问题，不写臆测条目；每条注明首次发现日期。

## 维护

- 相关脚本或 compose 服务变更时，同步检查引用它的 runbook。
- runbook 失效时状态改"过时"并指向替代文件，不直接删除。
