# 入口层文档规范（README.md / AGENTS.md / 索引）

新建或修改仓库根 `README.md`、`AGENTS.md`、`docs/README.md` 前必读本文件。

入口层独立于 WHY/WHAT/HOW 三层：它是**导航与契约**，不承载设计内容。铁律：入口层只做"指路 + 摘要"，细节一律链接到 docs/ 下对应文件，禁止在入口层维护第二份事实。

## 一、README.md（仓库根，给人看的入口）

定位：任何人 5 分钟内完成"这是什么 → 怎么跑起来 → 去哪里深入"。

**固定章节顺序**（可按需裁剪，但不得重排）：

1. 一句话定位 + 关键链接（指向 docs/）
2. 快速开始（最小可运行命令序列）
3. 访问入口/使用方式（表格）
4. 初始化步骤（有序列表）
5. 目录结构（带一行注释的树）
6. 环境注意事项（只放"会咬人"的坑，细节链到 runbooks/）

规则：

- 只写**当前生效**的信息；历史与理由链到 why/ 和 adr/。
- 快速开始必须来自实际验证过的命令；涉及脚本时引用脚本名，不复制脚本内容。
- 超过 300 行说明承载了过多细节 → 把细节下沉到 docs/ 对应层，README 留摘要 + 链接。

## 二、AGENTS.md（给 Agent 看的契约）

定位：Agent 工作的单一事实源——定位、约定、环境坑、路线图。每个 Agent 进项目必读，因此**正确性优先于详尽性**。

**固定章节**：项目定位 → 关键文档 → 项目技能（.agents/skills/ 索引）→ 硬性约定 → 部署/验证 → 已知环境坑 → 路线图。

规则：

- **同步触发**：任何被 AGENTS.md 提及的内容（目录结构、脚本名、端口、约定）发生变化时，同一个提交内必须更新 AGENTS.md。这是强制要求，不是建议。
- 硬性约定只写"违反会出事故"的规则（行尾、密钥、授权）；风格类偏好不进 AGENTS.md。
- 已知环境坑条目必须来自实测，注明症状与对策；与 runbooks.md 中登记的环境坑保持一致（同一事实两处写时，以 AGENTS.md 为准，runbook 行内注明引用）。
- 新增 `.agents/skills/` 下技能时，在"项目技能"一节登记一行。

## 三、docs/README.md（文档索引）

定位：docs/ 下所有文档的目录与状态总表，人和 Agent 都从这里进入。

**格式**：

```markdown
# 文档索引

| 文档 | 路径 | 层/域 | 状态 |
|------|------|-------|------|
| 需求-业务 | requirements/business.md | requirements | 生效 |
| Manager 规格 | what/manager.md | what | 生效 |

## 阅读路径
- 想了解为什么做：why/ → requirements/business.md
- 想集成/调用：what/
- 想改实现：how/ → 对应 runbooks/
- 想操作部署：runbooks/
```

规则：

- 每篇文档恰好一行；新建/拆分/废弃文档时同一个提交内更新本表。
- 状态字段与文件内元信息头的状态一致（草稿|生效|过时）。
- 模块清单（模块名、对应各层文件）也在本文件维护。

## 四、部署与测试指导的归属（再次明确）

| 内容 | 归属 |
|------|------|
| 部署/初始化/排障/验证操作步骤 | `docs/runbooks/`（细则见 runbooks.md） |
| 部署机制原理（为什么这样部署） | `docs/how/deployment.md` |
| 测试策略与契约（测什么、验收标准） | `docs/what/` 对应模块 + `requirements/` 验收字段 |
| 测试执行操作（怎么跑测试） | `docs/runbooks/` |
| 5 分钟最小上手 | 根 `README.md`（细节链到 runbooks/） |

## 五、mkdocs/ 生成层（用户文档）

- `mkdocs/docs/` 是 **Agent 生成、人审后发布**的用户文档层，与 docs/（开发文档）分属不同受众，禁止互相复制内容；需要交叉时互相链接。
- 人工不直接在 mkdocs/docs/ 下新建文件；生成物的组织约定（nav、front-matter）由 Manager 任务框架负责，约定变更记录进 `docs/adr/`。
