# 业务需求（BR）

> 版本：v1.1 · 日期：2026-09-02 · 状态：生效
> 定位：立项层面的业务动机——"为什么做"。拆分自旧文档 `../01-需求分析与选型.md` §1.2。

### BR-001 统一管理代码、CI 与测试
- 状态: 生效 | 上层: - | 优先级: P0
- 描述: 代码托管、CI 流水线、测试执行与报告在同一套环境内闭环管理。
- 验收: 从代码 push 到测试报告归档的全链路在环境内完成，无需外部 SaaS。

### BR-002 Agent 定时代码分析产出结构化文档
- 状态: 生效 | 上层: - | 优先级: P0
- 描述: AI Agent 按调度自动分析代码，产出结构化（WHY/WHAT/HOW）文档并发布。
- 验收: 配置一次后无需人工干预，文档站按调度周期更新。

### BR-003 Agent 比对代码与需求发现 gap
- 状态: 生效 | 上层: - | 优先级: P1
- 描述: Agent 将代码实现与需求条目比对，输出偏差（gap）清单。
- 验收: 需求机器可读（带 ID 条目化）；gap 报告能指出具体需求 ID 与代码位置。

### BR-004 Agent 生成提交/增量报告
- 状态: 生效 | 上层: - | 优先级: P1
- 描述: Agent 基于 commit/diff 自动生成可读的提交摘要与增量报告。
- 验收: 每日/每次合并可产出报告并送达对应角色。

### BR-005 Agent 辅助提取通用功能单独管理
- 状态: 生效 | 上层: - | 优先级: P2
- 描述: Agent 辅助从业务代码中提取通用功能，沉淀为独立仓库/包。
- 验收: 提取结果发布到内部包注册表，可被其它项目引用。

### BR-006 Agent 辅助提取知识 know-how
- 状态: 生效 | 上层: - | 优先级: P1
- 描述: Agent 从代码/会话中提炼可复用经验，进入知识库。
- 验收: 知识卡片经人工确认后入库且可被语义检索命中。

### BR-007 人工信息与 AI 产出物理隔离
- 状态: 生效 | 上层: - | 优先级: P0
- 描述: 用户补充的信息与 AI 分析产出在存储与展示上明确区分，互不混淆。
- 验收: 任一产物可判定来源（human/ai）；需审核的 AI 产出未经人审不得转正；工程显式启用直接发布时，配置与每次发布均可审计；项目经验上升为全局资产始终需要人工审核。

### BR-008 权限区分（开发 vs 老板）
- 状态: 生效 | 上层: - | 优先级: P0
- 描述: 开发（dev）与管理层（boss）看到不同范围的内容与入口。
- 验收: 同一账号体系下，boss/dev 登录后可见的报告、知识库区域、入口不同。

### BR-009 编译打包保护 prompt 与流程代码
- 状态: 生效 | 上层: - | 优先级: P2
- 描述: 自研 Agent 流程代码与 prompt 资产在交付物中不可读。
- 验收: 交付镜像中无源码层、无明文 prompt。
