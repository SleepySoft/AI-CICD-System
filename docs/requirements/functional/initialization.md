# 功能需求：Web 初始化与环境设置（INIT）

> 版本：v1.7 · 日期：2026-09-05 · 状态：生效
> 定位：Chronicler 首次初始化、组件批量部署与后续环境协调的功能需求；不定义组件自身业务配置。

### FR-INIT-001 首次启动进入受限引导
- 状态: 生效 | 上层: UR-001, UR-009 | 优先级: P0
- 描述: 从未完成初始化的实例以受限引导模式启动，只开放健康检查、初始化页面和初始化 API，不启动任务调度、组件自启及普通业务 API。
- 验收: 在无 `.env`、无初始化记录的干净安装上执行主入口可打开初始化页；工程、任务、用户管理等普通 API 均不可用。

### FR-INIT-002 分步向导与状态恢复
- 状态: 生效 | 上层: UR-001, UR-009 | 优先级: P0
- 描述: 初始化界面按环境预检、部署方案、基础配置、管理员、组件配置、计划确认、执行和完成八个阶段引导，并持久化草稿与执行进度。
- 验收: 任一阶段刷新或关闭浏览器后重新打开，非秘密字段与已完成步骤可恢复；界面明确指出当前步骤、阻塞原因和下一步。

### FR-INIT-003 环境预检
- 状态: 生效 | 上层: UR-001 | 优先级: P0
- 描述: 执行前检查安装目录与数据目录可写、Docker 可达及版本、Compose 可用、端口冲突、组件清单合法性和已有资源，并把问题分为阻塞、警告、通过。
- 验收: Docker 不可达或必需端口冲突时禁止执行并给出可操作的修复说明；警告项可由用户确认后继续。

### FR-INIT-004 部署方案与依赖解析
- 状态: 生效 | 上层: UR-001, UR-009 | 优先级: P0
- 描述: 用户可选择仅 Chronicler、推荐底座、完整底座或自定义组件方案；系统根据组件声明自动补齐传递依赖、检测冲突并说明自动选择原因。
- 验收: 选择依赖其它组件的组件后，预览中显示完整依赖闭包和选择来源；存在依赖环或冲突时不得生成可执行计划。

### FR-INIT-005 配置收集与秘密保护
- 状态: 生效 | 上层: UR-001, UR-009 | 优先级: P0
- 描述: 向导按组件声明生成配置表单，支持默认值、格式校验、随机生成秘密和已有 `.env` 的脱敏导入；普通读取 API 不得回传秘密，并在计划确认后提供一次性凭据显示与机器密钥下载。
- 验收: 必填项无效时无法进入计划确认；保存后刷新页面只显示“已设置”；一次性导出仅包含本次进程中新输入的凭据且第二次请求被拒绝；下载 JSON 只含账号与机器密钥类明文，口令仅页面一次性完整显示、不写入任何文件；日志、计划快照和诊断导出均不含秘密明文。

### FR-INIT-006 可审阅执行计划
- 状态: 生效 | 上层: UR-001, UR-009 | 优先级: P0
- 描述: 改变系统前生成确定的执行计划，逐项展示将跳过、创建、启动、等待、配置、验证和需要重启的动作，并单独标识破坏性动作。
- 验收: 未确认计划不得执行；相同输入与环境快照生成相同计划摘要；所有破坏性动作均需二次确认且默认不选中。

### FR-INIT-007 批量执行与实时进度
- 状态: 生效 | 上层: UR-001, UR-009 | 优先级: P0
- 描述: 系统按依赖图并行执行互不依赖的组件，单组件内部依次完成部署、就绪等待、配置和验证；界面同时展示总体进度、组件状态和脱敏日志。
- 验收: 至少两个无依赖组件可并行执行；依赖组件只在前置组件验证成功后开始；失败组件及受其阻塞的组件在界面可区分。

### FR-INIT-008 幂等重试与中断续接
- 状态: 生效 | 上层: UR-001, UR-009 | 优先级: P0
- 描述: 每个初始化步骤具备检查后执行语义并持久化输入摘要、尝试次数和结果；中断后可从最后一个未成功步骤续接，也可仅重试失败组件。
- 验收: 执行中重启 Chronicler 后，已成功且输入未变化的步骤不会重复产生资源；失败步骤重试不会创建重复客户端、账号或认证源。

### FR-INIT-009 组件自描述初始化契约
- 状态: 生效 | 上层: UR-009 | 优先级: P0
- 描述: 每个组件可在自身目录声明方案标签、依赖、冲突、资源提示、配置字段、就绪检查及可选初始化 hook；核心初始化模块不得包含组件名称分支。
- 验收: 新增一个符合契约的外置组件后，无需修改初始化模块即可出现在自定义方案中，并能生成表单、加入依赖计划和执行检查。

### FR-INIT-010 初始化完成与环境设置中心
- 状态: 生效 | 上层: UR-001, UR-009 | 优先级: P0
- 描述: 仅当基础配置、本地管理员及所有必需组件验证成功后才可完成初始化；完成后关闭未认证引导入口，同一模块转为仅 admin 可用的环境设置中心。
- 验收: 初始化完成后原一次性引导凭据不可再访问写接口；admin 可在设置中心为新增组件生成增量计划，普通用户被拒绝。

### FR-INIT-011 初始化记录与诊断
- 状态: 生效 | 上层: UR-001, UR-009 | 优先级: P1
- 描述: 系统保留每次计划与执行的状态、步骤、耗时、错误分类和审计记录，并提供不含秘密的诊断导出。
- 验收: admin 可查看历史初始化运行及每步结果；导出包经已登记秘密值扫描无匹配项。

### FR-INIT-012 恢复式重新初始化（旧数据保留与收敛）
- 状态: 生效 | 上层: UR-001, UR-009 | 优先级: P0
- 描述: 完成初始化后经本机恢复路径重新进入向导时，系统默认保留并复用既有 `.env` 秘密、数据目录与已部署容器，以幂等检查-执行将现实收敛到声明状态；向导不提供一键清除数据的“全新初始化”路径，可能令既有数据不可用的动作必须在计划中单独标识、默认不选中并二次确认。
- 验收: 重开引导后重跑初始化，未显式修改的秘密字段保持旧值，已运行容器被复用而非并行重建第二套；含既有数据的组件密钥轮换在计划确认阶段列为破坏性动作并提示后果；任何路径下向导均不出现自动删除业务数据的选项。决策见 ADR-0039。

### FR-INIT-013 秘密再导出与重置（按类型分级）
- 状态: 生效 | 上层: UR-001, UR-009 | 优先级: P0
- 描述: 初始化完成后，admin 可对机器密钥类秘密（encryption-key/client-secret/api-token/access-key）执行经审计的再导出；口令类秘密（password）不提供明文再导出，忘记时通过重置恢复——生成新口令并由组件 hook 对齐组件内账号；任何秘密可显式重置，rotation_risk 为 critical 的秘密重置必须列为计划破坏性动作并提示数据后果。
- 验收: 密钥再导出仅限 admin、产生审计记录且响应 no-store，审计记录不含秘密值；口令类秘密的任何 API 均不回传明文；口令重置后旧口令失效、新口令可用；critical 秘密重置默认不选中且需二次确认。决策见 ADR-0040。

### FR-INIT-014 秘密加密快照与主密钥恢复
- 状态: 生效 | 上层: UR-001, UR-009 | 优先级: P0
- 描述: 初始化生成与 `.env` 分离保管的主密钥（系统唯一副本 chmod 600、永不入库/落 data），明文仅在初始化完成时向操作者展示一次；每次 `.env` 持久化同时生成全部秘密的 age 兼容加密快照，快照密文可安全入库、随备份或异地拷贝；主机或 `.env` 丢失后凭主密钥加快照可导入重建全部秘密。
- 验收: 快照文件经扫描不含任何秘密明文，且可用标准 age 工具凭主密钥离线解密；错误主密钥解密失败；凭主密钥与快照在干净环境重建的秘密与原值逐键一致；主密钥与 `.env` 同时丢失时只能走 FR-INIT-013 重置路径。决策见 ADR-0041。

### FR-INIT-015 文件型秘密统一管理（签名证书/keystore 等）
- 状态: 生效 | 上层: UR-001, UR-009 | 优先级: P1
- 描述: 签名证书、keystore 等文件型秘密与文本秘密共用主密钥+加密快照机制：明文存 `secrets/files/`（chmod 600、永不入库/落 data），随快照整体加密归档与恢复；每个文件登记用途、属主与有效期并在过期前告警；CI 构建期以凭据注入临时取用，禁止打进镜像、明文入库或落 data/workspace。
- 验收: 文件型秘密随快照恢复后与原文件逐字节一致；快照及 CI 构建日志、产物经扫描不含秘密明文；有效期告警在阈值前触发；伴随口令（keystore 密码等）与对应文件关联并成套恢复。决策见 ADR-0042。

### FR-INIT-016 秘密作用域分权与审计
- 状态: 生效 | 上层: UR-009 | 优先级: P1
- 描述: 秘密按作用域（scope）归类，默认与工程一一对应并有 infra/signing 等系统作用域；员工以本人账号在线取用仅被授权作用域的秘密（页面显示/复制、不落文件），全部存取（读/写/导出/重置/上传/发放）写审计且不含秘密值；admin 可按作用域生成离线分发包（优先加密到接收者公钥，无密钥对的接收者用系统生成的高熵口令），发放事件写审计；离线包不可远程撤销，人员变动通过收回授权与轮换对应作用域秘密处理。
- 验收: 未授权作用域的秘密对普通用户不可读；审计记录含 actor、动作、scope、键名、时间且经扫描不含秘密值与包口令；分发包口令错误或接收者私钥不匹配均不可解密；收回授权后在线取用立即失效。决策见 ADR-0043、ADR-0044。

### FR-INIT-017 接收者密钥体系与提交即加密
- 状态: 生效 | 上层: UR-009 | 优先级: P1
- 描述: admin、CI 环境与（可选）员工各自持有 age 密钥对，私钥不出持有边界；秘密按授权接收者集合加密——系统自身秘密仅 admin 可解，工程/签名秘密为 admin + 授权接收者；外部提交秘密仅需接收者公钥即可加密存入，提交者不见明文且不可解密；交给 CI/CD 的秘密只在 CI 环境内解密注入。
- 验收: 密文包对接收集合外的私钥不可解密；提交接口不要求提交者持有任何私钥；admin 可为秘密增补接收者并重加密；CI 构建日志与产物经扫描不含秘密明文。决策见 ADR-0044。
