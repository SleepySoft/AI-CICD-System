# 设计原则

> 版本：v1.1 · 日期：2026-09-01 · 状态：生效
> 定位：全局生效的设计原则；修改本文件任何一条都必须有对应 ADR
> 关联需求：NFR-001 ~ NFR-009、BR-007

## 环境与交付

1. **组件目录是容器栈事实源**（NFR-006，ADR-0022/0027）：容器栈由 `chronicler/components/<name>/compose.yml` + `plugin.yaml` 定义，WSL/VM 镜像是其封装，不单独维护配置副本；supervisor 为独立交付件（ADR-0020）。
2. **最小依赖**：能用 Postgres 就不加 Redis，能用 APScheduler 就不上 Celery——少一个中间件少一份运维。
3. **全部免费含商用**（NFR-001，一票否决）：组件逐一核查授权，背景见 licensing.md。
4. **可复现**（NFR-005）：镜像全部 Dockerfile 版本锁定。
5. **按需启停**（NFR-003）：组件以 `autostart` 标记与首页工具面板控制启停，重负载组件默认不自启。

## 知识与文档

6. **Markdown 是知识的单一事实源**：向量库与 Web 展示都是可重建的索引层/展示层。
7. **来源隔离**（BR-007）：人工与 AI 产出分区存放、frontmatter 标注，AI 产出未经人审不转正。

## Chronicler 任务框架

8. **任务即配置**：每类分析任务 = 输入采集器 + Prompt 模板 + Agent 配置 + 输出处理器，全部入库可改。
9. **一切皆 Run**：每次执行产生含输入快照的 Run，可回溯、可重放。
10. **人审闭环**：Agent 产出统一先落待审区，人工确认后进入正式知识库/文档。
11. **宿主侧 supervisor**（ADR-0020）：产品本体是 docker 宿主侧进程，经本地 Docker API 控制组件生命周期，不再作为 compose 服务部署。

## 文档与协作

12. **文档即代码**：文档入 Git、按 WHY→WHAT→HOW 分层、需求带 ID 可追溯（规范见 `.agents/skills/docs-management/`）。
13. **密钥绝不入库**（NFR-002）：只提交 `.env.example`。

## 数据

14. **数据显式落宿主**（NFR-008，ADR-0012）：持久化数据一律 bind mount 到宿主目录，升级/重建容器不影响数据；禁用命名卷存业务数据。
15. **系统数据 Git 化**（NFR-009，ADR-0013）：可文本化数据以 Git 为事实源；DB 与二进制存储仅作可重建/可导出的运行时层。
