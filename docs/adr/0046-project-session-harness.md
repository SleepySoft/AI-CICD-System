# ADR-0046 工程常驻会话：任务与对话复用同一 ATR 会话

> 日期：2026-09-05 · 状态：已接受
> 关联：[ADR-0021 agent 用户自装 harness](0021-agent-user-installed-harness.md)（执行器扩展）；
> [ADR-0024/0025 组件即 SKILL](0024-component-as-skill.md)（上下文注入）；
> [ADR-0028 shadow 仓](0028-shadow-project-unified-artifacts.md)；ATR 为沙箱底座组件

## 背景

- 现状任务执行是一次性进程（harness `command_template`，如 `codex exec`）：每个 Run 从零重建
  上下文，工程背景反复喂入，token 重复消耗，且无法承接上一轮结论。
- ATR（terminal-runtime）已具备持久会话能力：tmux 后端跨服务重启存活、WS 增量事件、
  scrollback、锁与接管（lock/takeover）、对话式页面（/chat，2026-09-05 新增）。
- 用户诉求：系统为工程打开会话并注入相关信息；人可基于该会话对话；任务也可基于同一
  会话执行——工程的一切工作共享一份持续上下文，省 token。

## 决策

1. **工程↔会话绑定**：每个工程至多一个常驻会话 `atr-proj-<工程id>`，经 ATR API 幂等
   ensure 创建（tmux 后端，服务重启自动收养）。首次打开注入引导上下文：工程元信息 +
   已启用组件的 SKILL 摘要 + 工作纪律约束。
2. **harness 增加 `session` 模式**：任务输入经 ATR actions 发送到工程会话，
   `wait(input_likely_ready)` 收集输出；与现有一次性 exec 模式并存，按任务性质选择
   （日报类无状态任务仍适合 exec）。
3. **人机共用同一会话**：工程页嵌对话面板（ATR /chat）；任务执行持 ATR 锁，期间人的
   输入排队或显式接管（takeover 写审计）；对话与任务天然共享上下文。
4. **token 节省的边界明示**：常驻会话省的是重复上下文的输入 token，收益随轮次递减，
   上下文膨胀与漂移是固有代价；提供"重置会话"显式出口，不做无限累积，不做自动压缩
   （一期）。

## 备选方案

| 方案 | 否决原因 |
|------|---------|
| 维持每次任务新进程 | 现状；上下文重复喂入，token 浪费，无法承接前轮结论 |
| 全部任务强制 session 模式 | 日报等无状态任务不需要会话；会话漂移风险不应波及全部任务 |
| 对话与任务各开各的会话 | 违背"同一上下文省 token"的诉求；两份上下文反而更贵 |

## 后果

- 正面：上下文复用省 token；人机同语境（任务看得见人聊的、人看得见任务做的）；ATR
  资产（持久化/锁/对话页）全部复用，Chronicler 侧只加编排。
- 负面：会话漂移与上下文膨胀需治理（重置出口 + 后续摘要策略）；锁竞争需要 UX 表达
  （任务执行中对话面板的只读提示）；ATR 的 API token 纳入秘密库（scope=infra）。
- 实施拆分：P1 会话绑定 + 上下文注入 + 对话面板嵌入（人可用）；P2 session harness
  （任务跑在会话上）+ 锁协调；P3 token 统计与重置/摘要策略。
