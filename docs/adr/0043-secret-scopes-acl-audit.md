# ADR-0043 秘密作用域分权与审计：在线取用为主、离线分发包为辅

> 日期：2026-09-05 · 状态：已接受（离线包形态经 ADR-0044 修订：优先接收者公钥，口令为降级备选）
> 关联：[ADR-0041 主密钥 + 加密快照](0041-secret-snapshot-and-master-key.md)；[ADR-0042 文件型秘密](0042-secret-files-signing-assets.md)；[ADR-0040 秘密再导出与重置](0040-secret-reexport-and-reset-policy.md)

## 背景

- ADR-0041/0042 解决的是"单人（admin）灾备"。实际协作场景是多人：全部秘密（含签名文件）
  由 admin 统一持有（单一主密钥），但不同员工只应取用自己项目所需的那部分，且存取需要审计。
- 用户诉求的原始形态是"保存 N 个副本、不同密码取回、分配给不同员工"。离线加密副本有固有
  限制：**发出之后的使用不可审计、不可远程撤销**——审计与分权诉求只能由在线取用满足，
  离线包只能作为辅助形态。
- 现成方案调研（2026-09-05）：Infisical 核心 MIT 但**审计日志与 RBAC 为付费功能**（自托管
  同样需购企业许可），违反"组件全部免费（含商用）"约束；OpenBao/Vault 全免费且审计完备，
  但继承 Vault 的运维复杂度（unseal 自举、raft、token 生命周期），与"简单"诉求冲突；
  SOPS/age 多接收者无 ACL 无审计；Bitwarden/Vaultwarden 事件审计付费且面向人类口令，
  文件型秘密与 CI 场景弱，并会形成第二事实源。
- Chronicler 已有本地账号体系（admin/user）、工程管理和初始化秘密机制，无新增组件即可承载。

## 决策

秘密库引入**作用域（scope）分权**，在线取用为主、离线分发包为辅：

1. **归类保存**：每条秘密（文本或文件）归属一个 scope——默认与 Chronicler 工程一一对应，
   另有 `infra`、`signing` 等系统 scope。统一持有仍用单一主密钥（ADR-0041 不变）。
2. **在线取用为主**：员工以本人账号登录，仅可读取被授权 scope 的秘密（页面显示/复制，不落
   文件）；**全部存取写审计**——读、写、导出、重置、上传、发放，记录 actor、动作、scope、
   秘密键名、时间与来源，永不包含秘密值。撤销 = 收回授权，立即生效。admin 全量可见可管。
3. **离线分发包为辅**：确需离线副本（外包协作、应急）时，admin 按 scope 生成 age 口令模式
   加密包——**口令由系统生成高熵随机值、每包不同**（即"不同密码取回"），展示一次由 admin
   转交员工；发放事件写审计（含包指纹与接收人）。明示限制：离线包后续使用不可审计、不可
   远程撤销；人员离职/换岗的处置是**轮换该 scope 的秘密**（ADR-0040 重置路径）并视需重新
   发放。
4. 灾备副本（ADR-0041，admin 自持的主密钥+快照多副本）与分发包是两个目的不同的制品：
   前者为"防丢"，后者为"分权取用"，不得混用——分发包不含主密钥，永不含授权 scope 之外的
   秘密。

## 备选方案

| 方案 | 否决原因 |
|------|---------|
| 引入 Infisical 组件 | 审计与 RBAC 恰为付费功能（自托管亦同），违反免费含商用硬约束 |
| 引入 OpenBao / Vault 组件 | 运维复杂度高（unseal 自举、raft、token 管理），业界误配率高；与"简单"诉求直接冲突；其 unseal key 仍需主密钥式保管，鸡生蛋未解 |
| SOPS/age 多接收者加密 | 无 ACL、无审计，只是加密工具，不满足分权与审计诉求 |
| Bitwarden / Vaultwarden 组件 | 事件审计付费；面向人类口令，文件型秘密与 CI 场景弱；形成第二事实源 |
| 纯离线包分发（无在线模式） | 发出后不可审计、不可撤销，不满足审计诉求（仅作辅助形态保留） |

## 后果

- 正面：单一信任根（Chronicler + 主密钥），无新组件、无第二事实源；审计闭环（在线全量 +
  离线发放）；scope 与既有工程模型对齐；人员变动有明确处置路径（收回授权 / 轮换 scope）。
- 负面：需实现 scope 模型与 ACL、秘密存取审计、在线取密界面、分发包生成与发放流程；
  员工账号管理纳入 Chronicler 用户体系（已有本地账密）。
- 安全边界：审计与日志永不包含秘密值与包口令；分发包口令仅生成时展示一次；scope 授权
  变更本身也写审计。
- 同步更新：新增 FR-INIT-016 及追溯矩阵行；`what/initialization.md` 安全一节；实施时补
  秘密分发 runbook（发放、收回、轮换操作步骤）。
