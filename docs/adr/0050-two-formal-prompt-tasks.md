# ADR-0050 内置任务收敛为两套正式 Prompt

> 版本：v1.0 · 日期：2026-09-21 · 状态：已接受
> 定位：取代 ADR-0034 中“5 类任务映射 4 个 Prompt 家族”的内置任务布局。
> 关联：[ADR-0034](0034-task-prompt-family-registry.md)、[ADR-0049](0049-standard-prompt-context.md)、FR-MGR-007、FR-MGR-031

## 1. 背景

初版内置任务按报告章节和分析职责拆分，导致五个任务类型复用四个 Prompt 家族，任务边界、模板维护和运行上下文都出现重叠。统一 Prompt 运行上下文契约落地后，正式执行只需要两类稳定职责：面向管理者的运行报告，以及面向 Shadow 仓的项目认知资产维护。旧的四个 Prompt 家族已移动到 `recycled/prompts/`，不再作为运行模板。

## 2. 决策

1. 内置任务类型收敛为 `operational_reporter` 和 `project_cognitive_maintainer`，两者与同名 Prompt 一一对应。
2. `operational_reporter` 默认使用 `comprehensive` 模式；`project_cognitive_maintainer` 使用 `incremental` 模式。
3. 不保留旧任务类型兼容映射。旧内置任务定义在启动迁移中删除，随后为每个工程补齐两个新预置任务。
4. 历史 Run 不删除：迁移删除旧任务定义前先将关联 `task_runs.task_id` 置空，保留执行档案、报告、日志和发布记录供只读追溯。
5. 旧任务类型不允许新建或触发；Run 详情、列表、日志和报告接口必须容忍旧任务类型及损坏的历史 JSON，不得因架构切换破坏历史展示。

## 3. 备选方案

- **保留旧类型到新 Prompt 的映射**：会继续暴露已废弃职责，且旧模式字段与新契约语义不一致。
- **只隐藏旧任务定义**：数据库中仍存在无法执行的配置，调度器和 API 需要长期防御。
- **删除历史 Run**：破坏 Run 档案可追溯性，不符合 FR-MGR-005。

## 4. 后果

新工程和存量工程启动后都只看到两个内置任务。旧 Run 保留为历史事实，但不会再获得兼容执行路径。新增正式职责必须先扩展 Prompt 契约和任务注册，再新增任务类型；不得通过复活旧模板绕过契约。
