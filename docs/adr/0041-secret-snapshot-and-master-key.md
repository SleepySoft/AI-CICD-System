# ADR-0041 秘密的防丢持久化：主密钥 + 加密快照，导出 JSON 不含口令明文

> 日期：2026-09-05 · 状态：已接受
> 关联：[ADR-0040 秘密再导出与重置](0040-secret-reexport-and-reset-policy.md)（本文修订其一次性导出形态）；[ADR-0039 恢复式收敛](0039-reinit-recover-over-fresh.md)；[ADR-0013 系统数据 Git 化](0013-git-managed-system-data.md)；[ADR-0015 备份策略](0015-backup-strategy.md)

## 背景

- ADR-0040 解决了"密钥可再导出、口令可重置"，但留下两个缺口：
  1. 计划确认阶段下载的凭据 JSON 含全部秘密明文（含口令）。文件落盘即成为游离的明文炸弹——
     下载目录、同步盘、聊天转发都是常见泄漏源。
  2. 所有秘密只有一个物理副本：宿主 `.env`。主机损坏或误删即全量丢失，recover 无从谈起。
     随着组件增多，秘密数量持续增长，"安全且不容易丢"需要正式的持久化设计。
- 既有约束：compose 注入要求 `.env` 在宿主保持明文（chmod 600），此点不变；"机密永不落 data"、
  "密钥绝不入库"针对的是明文；组件全部免费（含商用）。

## 决策

引入**主密钥 + 加密快照**两层防丢结构：

1. 初始化时生成高熵**主密钥**，系统唯一副本存于 `secrets/master.key`（chmod 600，永不入库、
   永不落 `data/`）；主密钥明文仅在初始化完成时向操作者**展示一次**，系统不提供找回——操作者
   须转存密码管理器并离线备份一份。
2. 每次 `.env` 持久化时，用主密钥生成**全部秘密（含口令）的 age 兼容加密快照**
   `secrets/secrets.age`。密文可安全提交 git、随 ADR-0015 备份、异地拷贝——这是秘密的防丢
   恢复层；`age -d` 可不依赖 Chronicler 手工解密，避免工具锁定。
3. 主机或 `.env` 丢失后，操作者在干净环境提供主密钥 + 快照即可**导入重建** `.env`（recover 的
   物质前提）；主密钥与 `.env` 同时丢失时，按 ADR-0040 走重置路径（口令重置、`critical` 密钥
   认损）。
4. **修订 ADR-0040 第 4 条**：计划确认阶段的下载 JSON **只含账号与机器密钥类明文，不含口令**；
   口令仅在页面一次性完整显示（用户主动点击），直接转存密码管理器，不写入任何文件。

## 备选方案

| 方案 | 否决原因 |
|------|---------|
| 凭据 JSON 维持含口令明文 | 游离明文文件是最常见的凭据泄漏源；口令已有"页面一次性显示 + 密码管理器"路径，无需落文件 |
| 明文 `.env` 提交私有仓库或随备份 | 违反"密钥绝不入库"；一次误推送或备份外发即全量泄漏 |
| 引入 Vault / OpenBao 组件 | 单宿主场景过度工程；unseal 密钥仍需人保管，鸡生蛋问题未解；多主机化时可另行决策 |
| SOPS（按字段加密的 YAML） | 面向 git-diff 友好的场景；本需求是整文件快照 + 导入恢复，age 整文件加密更简单，恢复不依赖额外概念 |
| 主密钥也存数据库等系统内位置 | 主密钥与密文同地存放等于没加密；必须与密文分离，且系统不留第二份明文 |

## 后果

- 正面：丢失场景全覆盖——丢 `.env` 用快照+主密钥重建；丢主机用 git/备份中的快照 + 密码管理器
  中的主密钥；两者都丢才退化到 ADR-0040 重置路径。
- 正面：密文快照可入库，让秘密恢复搭上 git 的版本管理与异地能力（ADR-0013 精神的延伸），
  "明文密钥绝不入库"规则不变。
- 正面：消除游离明文 JSON；口令从生成到密码管理器不经过任何落盘文件。
- 负面：初始化需新增主密钥生成/一次性展示、快照随持久化写入、导入恢复三个流程；`.gitignore`
  与 AGENTS.md"密钥绝不入库"需加"密文快照例外"一行修订；备份 runbook 需说明快照随备份的
  安全性依据。
- 安全边界：主密钥系统内仅 `secrets/master.key` 一份（chmod 600）；审计与日志永不包含主密钥
  和秘密值；快照必须经"无秘密明文"扫描验收。
- 同步更新：FR-INIT-005 修订导出形态、新增 FR-INIT-014 及追溯矩阵；`what/initialization.md`
  §2.2/§2.5/§2.8；实施时修订 AGENTS.md 与 `.gitignore`。
