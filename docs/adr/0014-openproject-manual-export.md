# ADR-0014 OpenProject 导出为手工入口（不做定时导出与远端推送）

> 日期：2026-08-26 · 状态：已接受
> 关联：需求 NFR-009；ADR-0013（细化其导出补偿机制，非推翻）、ADR-0011

## 背景

ADR-0013 确定"可文本化数据以 Git 为事实源，DB 型服务以导出补偿"，但导出机制当时留待任务管理落地时定。决策时刻已明确的判断：**定时导出并上传远端（GitHub）没有意义**——审计与"AI 离线文本视图"都是低频需求，无人消费时定时快照只会产生噪音提交，自动推送还把 API token 的使用面扩大到无人值守环节。

## 决策

OpenProject 导出做成**手工入口**：`scripts/export-openproject.sh` 由人手动运行，产出 JSON 全量（项目/工作包/关系/状态）+ Markdown 摘要快照到本地目录（默认 `exports/openproject/<时间戳>/`）；需要入 Git 审计时，把输出目录指向某个 Git 仓库后人工审查、自行 commit。不做定时任务，不自动推送远端。

## 备选方案

| 方案 | 否决原因 |
|------|---------|
| 定时 cron 导出 + 自动 push 远端 | 无消费方时产生噪音提交；token 进入无人值守环节，扩大泄露面；快照节奏脱离真实审计需求 |
| 不导出 | 违背 NFR-009 的可审计要求；AI 无法获得离线文本视图 |
| Manager 内嵌导出按钮 | 保留为后续增强（M3 之后再议）；当前脚本入口已够用，不提前建设 |

## 后果

- 正面：零常驻开销、无凭据外发；快照节奏由人掌控，导出的 Markdown 可直接喂给 AI 做离线分析。
- 负面：快照可能滞后，审计时点依赖人记得跑脚本；导出内容不含附件与 DB 内部状态。
- 同步：`scripts/export-openproject.sh`（新增）、`.env.example`（新增 `OPENPROJECT_API_KEY`）、`.gitignore`（排除 `exports/`）、traceability.md NFR-009 行、`.agents/skills/openproject/`（Agent 操作规范，引用本决策）。
