# ADR-0044 多接收者密钥体系：系统秘密仅 admin 可解，工程秘密按接收者集合加密

> 日期：2026-09-05 · 状态：已接受
> 关联：[ADR-0041 主密钥 + 加密快照](0041-secret-snapshot-and-master-key.md)；[ADR-0042 文件型秘密](0042-secret-files-signing-assets.md)；[ADR-0043 作用域分权与审计](0043-secret-scopes-acl-audit.md)（本文修订其离线包形态）

## 背景

- ADR-0041 定义单一主密钥 + 快照（灾备）；ADR-0043 引入 scope 分权与口令模式离线包。用户进一步
  明确密钥体系的目标形态：
  1. **本系统自身秘密**（组件口令、OIDC 秘密等）只有 admin 手中的密钥可解；
  2. 其它秘密与秘密文件由 admin 密钥加密一份（灾备，ADR-0041），admin 解密后可用**另一把密钥
     单独加密一份**交给开发或 CI/CD；
  3. 最终形态：秘密**只在 CI/CD 内部解密和使用**，外部（含提交者）看不到明文；
  4. 当前阶段预留该体系，先允许单个秘密/证书的显示与导出以满足使用需求。
- age 原生支持多接收者加密（同一密文可被授权集合内任一私钥解开）与公钥加密（加密不需要任何
  私钥），上述目标形态可直接映射，无需自研加密协议。

## 决策

采用**多接收者密钥体系**：

1. **每主体一把 age 密钥对**：admin、每个 CI 环境、（可选）员工各自持有；私钥不出持有边界
   （admin 私钥即 ADR-0041 主密钥；CI 私钥仅存 CI 凭据库）。公钥可公开登记（含指纹）。
2. **按接收者集合加密**：系统自身秘密只加密给 admin 接收者——仅 admin 私钥可解；工程/签名类
   秘密加密给 admin + 授权接收者（如该项目的 CI）。admin 通过"解密 → 按新接收者集合重加密"
   增补接收者；回收接收者依赖对应秘密轮换（同 ADR-0043 的离线包撤销语义）。
3. **提交即加密（write-only）**：外部/开发提交秘密或证书时，用接收者公钥加密后存入即可——
   提交者全程不见明文，事后也无法解密。
4. **CI 内解密**：交给 CI/CD 的秘密以 CI 公钥加密；CI 私钥只存于 CI 凭据库，秘密仅在构建
   代理内解密注入（构建日志自动掩码），任何外部方不可见明文。
5. **分期实施**：一期以 ADR-0040/0043 的 admin 单独显示/导出承载使用需求；二期实现接收者
   集合管理、提交即加密与 CI 密钥对接入。ADR-0043 离线包的口令模式降级为"接收者无法管理
   密钥对时的备选"，优先使用接收者公钥。

## 备选方案

| 方案 | 否决原因 |
|------|---------|
| 自研对称密钥分发（每 scope 一把对称钥） | 解密密钥的分发本身需要安全信道；公钥模型让"提交"与"分发"都不需要传输解密密钥 |
| 口令包为主（ADR-0043 原案） | 口令需安全转交、存在弱口令风险、无法表达"提交者不可见"；保留为无密钥对接收者的降级形态 |
| 全部秘密仅 admin 单密钥，CI 用时在线拉取 | 构建强依赖 Chronicler 在线；CI 侧无加密静置副本，灾备与使用割裂 |

## 后果

- 正面："外部看不到明文"成为密码学保证而非流程约束；提交者不可见明文；密文包即 CI 注入的
  载体（衔接 ADR-0042）；admin 单密钥灾备（ADR-0041）不变。
- 负面：需实现接收者密钥对管理（生成/登记/指纹展示）、按集合加解密、CI 私钥托管约定；
  员工/CI 私钥丢失的处理流程（admin 重加密补发）。
- 安全边界：CI 私钥离开 CI 凭据库即视为泄漏——轮换该密钥对并重加密相关包；审计不含私钥、
  口令与秘密值。
