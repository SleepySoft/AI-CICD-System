# ADR-0042 文件型秘密（签名证书/keystore）纳入统一秘密管理

> 日期：2026-09-05 · 状态：已接受
> 关联：[ADR-0041 主密钥 + 加密快照](0041-secret-snapshot-and-master-key.md)；[ADR-0040 秘密再导出与重置](0040-secret-reexport-and-reset-policy.md)

## 背景

- ADR-0041 的快照面向短文本秘密（口令/密钥，key=value 形态）。开发期还有一类**文件型秘密**：
  Android keystore（`.jks`/`.keystore`）、Apple 签名证书（`.p12`）与 provisioning profile、
  服务账号 JSON、TLS 私钥等二进制或长文本文件，无法自然地塞进 `.env`。
- 这类秘密的丢失后果按 ADR-0040 的分级看是最严重的一档：口令可重置，加密密钥丢失可认损重建，
  而 **Android 签名密钥丢失且未加入 Play App Signing 时，应用永远无法再发布更新**——它是
  "不可替换"级资产，对"不容易丢"的需求最强。
- CI（Jenkins + toolchain-android 镜像）构建签名时需要安全取用这些文件：不能明文入库、不能
  打进镜像、不能落 `data/workspace/`（工作区可由 git 重建，不入备份）。

## 决策

统一秘密管理机制直接扩展到文件型秘密，快照格式从"文本 KV"升级为"**tar 归档 + age**"：

1. **工作层**：明文文件存 `secrets/files/<用途名>/`（chmod 600，永不入库、永不落 `data/`），
   与 `.env` 同级、同保护规则。
2. **恢复层**：每次持久化把 `secrets.txt`（全部文本秘密）与 `secrets/files/` 整体打进 tar，
   再 age 加密为 `secrets/secrets.age`——仍然只有**一个主密钥、一个快照文件、一条恢复命令**。
3. **元数据登记**：每个文件型秘密登记用途、属主（哪个工程/CI 任务）和有效期（证书过期时间），
   系统在过期前告警——证书过期是签名事故的高发来源。
4. **使用侧**：CI 构建通过凭据注入在构建期临时取用（凭据绑定挂载进构建容器），用完即弃；
   禁止打进镜像、禁止明文入库、禁止落 `data/workspace/`。
5. 文件型秘密的伴随口令（keystore 密码、key alias 密码）按 ADR-0040 口令类规则管理，并与对应
   文件关联登记，恢复时成套还原。

## 备选方案

| 方案 | 否决原因 |
|------|---------|
| 把文件 base64 后塞进 `.env` 当普通秘密 | `.env` 膨胀易错、compose 注入语义被污染；二进制 roundtrip 易损坏 |
| 单独引入证书管理体系（Vault/cert-manager 等） | 又造一个信任根和管理面，违背统一管理诉求；单宿主过度工程 |
| 只登记元数据，文件靠人自行备份 | 最容易丢的恰恰是最不能丢的；人肉备份无版本、无异地、不可验证 |
| 快照拆成文本、文件两个文件 | 恢复时要同时管两份，违背统一恢复原则；单归档更简单 |

## 后果

- 正面：最不可替换的资产获得最强防丢能力（git 版本史 + 异地密文副本）；全部秘密仍由同一个
  主密钥一条命令恢复；过期告警消除一类高发签名事故。
- 正面（互补建议，非系统行为）：若经 Google Play 分发，应用应同时加入 Play App Signing——
  Google 托管正式签名 key，本地只留 upload key，把"永久不可更新"降级为"可联系支持重置"。
  **不经 Google 体系分发（官网直发/企业内部/国产市场）时该建议不适用**：keystore 即应用唯一
  身份证，任何渠道均无重置路径，本机制是唯一防线——应额外做主密钥与快照的多份物理隔离离线
  副本，并在旧 key 存活期间预置 APK Signature Scheme v3.1 轮换谱系（仅旧 key 未丢时有效）。
- 负面：快照体积增大（keystore/证书通常 KB~MB 级，可接受）；初始化与环境设置中心需新增文件
  上传/下载/元数据登记界面；CI 侧需要签名凭据注入的配置约定（runbook）。
- 安全边界：文件型秘密与文本秘密同规则——明文不出宿主、审计不含内容、构建日志与产物不得
  出现明文。
- 同步更新：新增 FR-INIT-015 及追溯矩阵行；`what/initialization.md` §2.5；实施时补充 CI 签名
  凭据 runbook。
