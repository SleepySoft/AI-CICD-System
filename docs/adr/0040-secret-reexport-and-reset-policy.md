# ADR-0040 秘密再导出与重置：按 secret_type 分级

> 日期：2026-09-05 · 状态：已接受（第 4 条一次性导出形态经 ADR-0041 修订：下载 JSON 不再含口令明文）
> 关联：[ADR-0039 重新初始化采用恢复式收敛](0039-reinit-recover-over-fresh.md)；[ADR-0038 受限引导模式与声明式组件初始化](0038-bootstrap-mode-and-declarative-initialization.md)

## 背景

- ADR-0039 确立重新初始化为恢复式收敛（recover），但 recover 旧环境的前提是持有旧秘密——尤其是
  加密密钥类秘密。现行规格（FR-INIT-005、what/initialization.md §2.5）规定秘密只在计划确认阶段
  一次性导出、之后"不反向读取 `.env`"；一旦用户未妥善保存导出文件，密钥即永久丢失，recover 不成立。
- 口令与机器密钥的风险属性不同：口令由人用于登录，丢失后**重置**即可恢复访问（旧口令随即失效）；
  机器密钥（尤其 `encryption-key`）用于加解密存量数据，丢失即数据不可用，除"找回原值"外没有
  第二条恢复路径（实测：Outline 丢失 `SECRET_KEY` 后，用户 OAuth token、webhook 签名密钥、
  OAuth client secret、用户 JWT secret 全部不可读，只能删/轮换重建）。
- compose 环境注入模型决定所有秘密物理上以明文存在于宿主 `.env`（chmod 600），产品面能决定的
  是"谁、经什么途径、可以再次看到哪类秘密"，而非消灭明文存储本身。

## 决策

初始化完成后的秘密管理按 `setup.yaml` 已声明的 `secret_type` 分级：

1. **机器密钥类**（`encryption-key` / `client-secret` / `api-token` / `access-key`）：admin 可在
   环境设置中心**再导出**（从 `.env` 回读）；每次再导出写审计记录（不含秘密值），响应 `no-store`。
2. **口令类**（`password`）：任何 API 均不回传明文，不提供再导出；忘记口令的恢复路径是**重置**——
   生成或输入新口令，由组件 hook 以幂等方式对齐组件内账号，旧口令即时失效。
3. 任何秘密都允许显式**重置**（覆盖写入 `.env` + hook 对齐现实）；`rotation_risk: critical` 的秘密
   重置必须列入计划的破坏性动作，默认不选中、二次确认并提示后果（旧加密数据、会话、令牌与集成
   不可恢复）。
4. 计划确认阶段的一次性导出语义不变，仍是初始化时获取口令明文的唯一时机。

## 备选方案

| 方案 | 否决原因 |
|------|---------|
| 全部秘密开放再导出 | 口令明文暴露面不必要地扩大；口令可重置即恢复，无再导出必要 |
| 维持现状：全部秘密不可再导出 | 丢密钥即丢存量数据，ADR-0039 的 recover 语义不成立 |
| 引入独立加密密钥库，秘密密文存储 | compose 注入模型下 `.env` 明文不可消除，额外密钥库属首版过度工程；可作为后续增强另行决策 |

## 后果

- 正面：recover 的前提成立——机器密钥随时可找回；口令暴露面最小化（明文只在初始化一次性导出时
  离开 `.env`）；重置路径统一为"覆盖 `.env` + hook 对齐"，与 ADR-0039"凭据漂移以 `.env` 为准"一致。
- 负面：需新增密钥再导出 API（admin 限定、审计、no-store）、口令重置动作与 hook 契约扩展（hook 须
  支持"对齐凭据"，而非仅"存在即跳过"——与 ADR-0039 记录的实现债同源）；环境设置中心需增加秘密
  管理界面。
- 安全边界：再导出仅限 admin 会话；审计记录永不包含秘密值；口令明文除初始化一次性导出外不离开
  `.env`。
- 同步更新：新增 FR-INIT-013 及追溯矩阵行；`what/initialization.md` 安全一节记录分级策略。
