# ADR-0051 已初始化的数据加密密钥禁止直接替换

> 日期：2026-09-27 · 状态：已接受
> 关联：FR-INIT-012/013；[初始化规格](../what/initialization.md)；补充 ADR-0040/0045

## 背景

Outline 旧 boss 的会话密钥和 OAuth 令牌不能用当前 SECRET_KEY 解密，新 dev 账号正常。
运行容器与秘密库的值一致，普通登录巡检只覆盖 dev，无法发现旧账号故障。
现有 critical 标签仅提示风险；秘密轮换、导入和初始化仍能替换加密密钥。
启动迁移以明文 .env 强制覆盖秘密库，Compose 又可能优先采用进程中的旧环境变量。

## 决策

`encryption-key` 且 `rotation_risk=critical` 的既有秘密只允许保持原值；常规操作拒绝替换、
删除和元数据降级，更换必须通过备份与加密数据迁移的专门维护流程。

## 备选方案

| 方案 | 否决原因 |
|------|----------|
| 保留二次确认后直接替换 | 确认不能使旧密文可解密，仍会使数据不可用 |
| 发现故障后全局回退密钥 | 新旧账号可能使用不同密钥，回退会破坏新数据 |
| 自动清空损坏认证记录 | 会无提示地使账号会话失效，且不适用于其它业务密文 |

## 后果

后端、初始化与强制导入统一保护；批量操作先检查受保护条目的冲突。
秘密库持久化失败不能继续写 .env 引用；明文 .env 与秘密库冲突时阻止启动迁移和自启。
Compose 采用本次渲染配置，剔除进程中的同名插值变量，显式安装路径保留。
Outline 在启动业务服务前检查既有认证密文；首次安装的空数据库允许继续初始化。

普通 Web/API 不再提供长期数据加密密钥的破坏性重置，用户需进行组件维护。
此保护不能阻止管理员直接修改数据库、宿主文件或外部 Docker 配置，也不能恢复已丢失的旧密钥。
当前契约与机制分别更新在 what/initialization.md、how/secrets-vault.md；操作见 runbooks/outline-auth.md。
