# ADR-0039 重新初始化采用恢复式收敛，不提供全新初始化路径

> 日期：2026-09-05 · 状态：已接受
> 关联：[ADR-0037 初始化收归单一入口](0037-single-entry-web-init.md)；[ADR-0038 受限引导模式与声明式组件初始化](0038-bootstrap-mode-and-declarative-initialization.md)；[ADR-0012 数据显式挂载宿主目录](0012-data-on-host-bind-mounts.md)；[ADR-0015 备份策略](0015-backup-strategy.md)

## 背景

- 2026-09-04 实测：经 `scripts/reset-initialization.py` 重开引导并重跑初始化时，环境中存在
  16 小时前旧栈留下的容器（postgres/redis/keycloak/gitea/caddy/jenkins/outline/mkdocs，挂在
  已弃用的 `aisystem_default` 网络）、旧凭据和已有业务数据。重跑暴露四类冲突：跨网络服务名
  解析失败、`.env` 新秘密与容器内旧凭据漂移、PostgreSQL 角色缺失、含既有数据的组件
  （Outline）面临加密密钥轮换即销毁会话/令牌/集成的后果。最终全部依靠人工逐项处置才把现实
  收敛到声明状态。
- ADR-0038 已否决"初始化失败时自动删除已创建的数据"，确立幂等重试优于破坏性回滚；
  `reset-initialization.py` 的实现策略（保留 `.env`、用户、工程、容器与业务数据，重跑时检查
  并复用已部署组件）与之一致，但该策略从未形成正式决策——向导与文档对"存在旧数据时重新
  初始化是什么语义"没有答案，操作时只能临场判断。
- "全新初始化"（清空数据重来）实质是删除 `data/` 下全部业务数据与容器，属不可逆运维操作；
  若放进安装向导，会把高危选择前置给未必理解后果的用户。

## 决策

重新初始化的唯一系统语义是**恢复式收敛（recover）**：保留并复用既有 `.env` 秘密、宿主数据
目录与已部署容器，执行器以幂等 check→apply 将现实收敛到声明状态；凭据漂移以 `.env` 为准，
由组件 hook 对齐现实，不反向改写 `.env` 迁就失控的现实。系统不在向导、API 或脚本中提供
"全新初始化 / 一键清空"路径；彻底重建只能由操作者按备份与恢复 runbook 显式手工执行
（备份 → 停栈 → 删除数据 → 重置初始化状态），属于运维行为而非安装能力。

配套语义：

1. **秘密复用优先**：`.env` 中已配置的秘密默认保留（界面留空即保持旧值）；仅显式输入新值
   才轮换。`rotation_risk: critical` 的字段（如加密密钥）轮换必须在计划确认阶段列为破坏性
   动作，并明示后果（旧加密数据、会话、令牌与集成不可恢复）。
2. **遗产资源收养**：预检发现同名容器或数据但不符合当前声明（网络、标签、端口漂移）时，
   给出收养/修复指引（如接入共享网络并配置服务别名），不并行起第二套同名服务。
3. **破坏性动作显式化**：凡可能令既有数据不可用的动作必须进入计划的 `destructive_actions`，
   默认不选中且需二次确认（FR-INIT-006）。

## 备选方案

| 方案 | 否决原因 |
|------|---------|
| 向导内提供 recover / 全新初始化双模式 | "全新"实质是删除全部业务数据，把不可逆选择前置给安装场景的用户；与 ADR-0038 的反破坏立场冲突 |
| 检测到旧数据即拒绝继续，要求手工清理 | 断点续装（NFR-004）与灾难恢复场景不可用；把系统应做的收养工作推给用户 |
| 静默清空数据以保证"干净的全新初始化" | 数据不可恢复，事故时扩大损失；违背数据显式落宿主（ADR-0012）所预设的备份前提 |

## 后果

- 正面：重新初始化行为可预期——重跑永远不丢数据；与 `reset-initialization.py`、
  `ensure_running` 的幂等语义、组件 hook 幂等约定及 ADR-0038 形成一致整体。本次事故中的
  人工处置（对齐凭据、收养网络、补建角色）成为明确的系统语义，而非临场发挥。
- 正面：破坏性重建仍然可达，但被显式运维流程（ADR-0015 备份 → 清空 → 重置）包裹，天然
  带有备份与多重确认。
- 负面（实现债）：recover 路径工程量增加——预检需识别遗产容器与网络漂移；组件 hook 需
  实现凭据对齐能力（以 `.env` 为准校正组件内管理员凭据，而非仅"存在即跳过"）；加密密钥类
  字段需在计划中自动生成轮换警告。以上逐组件、逐能力补齐。
- 同步更新：新增 FR-INIT-012 及追溯矩阵行；`what/initialization.md` 生命周期一节记录本
  语义；部署 runbook 补充"彻底重建"人工流程指引（备份前置）。
